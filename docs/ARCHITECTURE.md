# BeatForge Studio architecture

Song file in, validated five-difficulty Beat Saber map out — generated by the
bundled `beat-saber-mapping` skill, gated by refusal states, reviewed by
OpenAI Codex when requested, and released only on human VR evidence.

The website **never** uses the legacy `beatforge.place` chart generator. Every
generation request shells out to the canonical skill pipeline.

## Studio request flow

```
web/index.html ──POST /api/generate──► src/beatforge/api.py
                                            │  _run_job (background task)
                                            ▼
                                  src/beatforge/premium.py
                                            │  subprocess: generate_map.py
                                            │    --profile official-premium
                                            │    --full-spread
                                            │    --corpus-database <local sqlite>
                                            ▼
                    skills/beat-saber-mapping/scripts/generate_map.py
                                            │
             ┌──────────────┬───────────────┼────────────────┬──────────────┐
             ▼              ▼               ▼                ▼              ▼
      official_corpus  analyze_audio   artwork.py      choreography.py  validate_map.py
       (gate: sync)   (timing + grid)  (cover, palette) (CP-SAT hands +   (hard gates;
             │              │               │             realization)     exit 0/1)
             ▼              ▼               ▼                ▼
      corpus_incomplete  needs_anchors  needs_palette   map folder + qa_report.json
                                            + provenance (releaseGate flags)
```

### Bridge contract (`src/beatforge/premium.py`)

`run_premium_pipeline` builds the subprocess command and maps the skill's exit
code to a studio state:

| Exit code | Studio state | Meaning |
|---|---|---|
| 0 | `playtest_candidate` | Requested difficulties generated and locally validated |
| 1 | `invalid` | Hard validation failure |
| 3 | `needs_anchors` | Timing confidence insufficient; user anchors required |
| 4 | `corpus_incomplete` | Official corpus missing/unexplained extraction failures |
| 5 | `needs_palette` | No approved readable palette |

`--difficulty` may be repeated for a subset. `--continue-unconfirmed` is the
studio **Download anyway** path: unconfirmed grid, optional fallback palette,
never `timing_verified`, never `release_candidate`. Progress is streamed from
generator stderr (`BEATFORGE_PROGRESS` tab-separated stage, detail, optional
percent). A named playtest song (including Pacific Coast Highway) is headset
feedback, not the only fixture.

`api.py` then zips the map (`package_map`), summarizes `Info.dat`
(`summarize_map`), and re-reads `_beatforge/qa_report.json`: any error flips
`playtest_candidate` to `invalid`, otherwise the job becomes `review_required`.

`STUDIO_STATES` is the ten produced/consumed job states:
`needs_anchors`, `needs_palette`, `corpus_incomplete`, `validating`,
`review_required`, `playtest_candidate`, `studio_reviewed`,
`release_candidate`, `invalid`, `error`. `queued` and `running` are live
in-flight labels. `validating` is not terminal.

`_update_release_status` writes headset evidence into
`map/_beatforge/provenance.json`. `release_candidate` is off unless
`BEATFORGE_AI_RELEASE_ROUTE=1` (AI-routed review). Without that, the ceiling is
`studio_reviewed`.

## Skill pipeline stages

1. **Corpus gate** — `official_corpus.py` indexes the locally installed
   first-party Beat Saber library into a private sqlite database (default under
   `%LOCALAPPDATA%\Codex\beat-saber-mapping\`, resolved by
   `premium.corpus_database()`). The database and exact official event data
   never enter Git or provider bundles. Missing or unexplained first-party
   extraction failures block `official-premium` generation.

2. **Audio analysis** — `analyze_audio.py` decodes through pinned FFmpeg into
   integer sample positions, runs the external tracker ensemble
   (Beat This is the mix clock, BeatNet+ the challenger, All-In-One for sections;
   Demucs **`htdemucs_6s`** six stems when
   enabled, recorded in `analysis.json` as `demucs.requiredModel`), and builds a
   monotonic piecewise beat grid. Automatic timing approval requires Beat This
   and BeatNet+ to agree with median residual ≤ 10 ms and p95
   residual ≤ 20 ms; anything else exits `needs_anchors` for user or AI anchors,
   while the unconfirmed click still follows Beat This when it ran. After an AI
   timing review, both clocks are checked against the adopted grid.
   Internal onset detection may suggest anchors but never impersonates the
   ensemble. Outputs: `analysis.json`, `beat_grid.json`, `sections.json`,
   `audio_features.npz`, `click_track.wav`.

3. **Artwork and palette** — `artwork.py` extracts embedded cover art
   (ID3 APIC, FLAC pictures, M4A/MP4, OGG, supported WAV), falls back to an
   exact MusicBrainz → Cover Art Archive match (≥ 0.92 normalized confidence,
   duration within 2 s), and derives two saber colors that must clear CIEDE2000
   30 normally and 20 under protanopia/deuteranopia simulation. No readable
   pair → exit `needs_palette`. Provenance records source URL, image hash,
   extracted colors, adjustments, and user approval.

4. **Choreography** — `choreography.py` selects per-difficulty musical intent
   and searches color, lane, row, cut, hold lifecycle, bombs, and walls jointly
   with CP-SAT occupancy and kinematics (`joint-cp-sat`). Occupancy, chain
   minimum tails, and the post-hold same-hand lock live only in
   `scripts/safety_contract.py`. Overlapping windows (`JOINT_WINDOW` 64,
   overlap 10) retry an unfrozen overlap with prefix exits and prefix
   same-beat heads when a frozen seam makes the next window infeasible;
   stripping every chain is not the first fallback. An unsafe arc or chain
   may be realized as a note; the search does not relax kinematics to keep
   the hold. If joint SAT is infeasible, a two-stage SAT assigns hands then
   poses, then a post-note hazard SAT. Provenance must say `joint-cp-sat`
   only when requested holds actually survived. Beam search may only skip
   notes (density) or downgrade holds. Opposite-hand notes at hold tails are
   part of the hold pose domain. Lighting is still a coarse v3 show
   (~0.49 beat event floor, downbeats, hold heads, section peaks) and must
   not clone official event lists. `kinematics.py` enforces same-color swing
   feasibility, cross-hand clearance, post-hold recovery, bomb paths, and
   handclap safety.

5. **Validation and packaging** — `generate_map.py` writes v3.3 gameplay files
   with a v2.1 `Info.dat`, then runs `validate_map.py` as a subprocess. The
   validator hard-gates schema, timing provenance, same-hand flow, arc/chain
   ownership, collisions, and hazards into `_beatforge/qa_report.json`.

## Release states

`_update_release_status` gates each transition:

- `studio_reviewed` = local hard gates passed + at least one provider review
  passed with zero unresolved findings.
- `release_candidate` is disabled in the local studio. Turn it on only when
  rerouting maps through the independent AI review path
  (`BEATFORGE_AI_RELEASE_ROUTE=1`). Then it still requires `studio_reviewed` plus
  playtest evidence in provenance: full-speed clears on the requested
  difficulties, slow Expert/Expert+ when those maps exist, and a separate
  tester's fresh sight-read.

The software installs and launches the level for testing; it never claims a
physical VR playtest. Headset results are submitted by humans through
`POST /api/jobs/{id}/playtests`.

## Codex review layer (`src/beatforge/providers.py`)

The optional Codex review connector:

- The secret lives only in Windows Credential Manager (`BeatForge:codex`);
  it is injected into the Codex child process environment alone and is
  redacted from any surfaced output.
- `prepare_review_bundle` builds a Codex review zip from a safe file list that
  excludes corpus databases, records its SHA-256 as `bundleHash` with a
  one-time consent token, cost ceiling, and rights attestation.
- `run_review` verifies the token (constant-time), bundle hash (before *and*
  after), expiry, attestation, and budget; re-hashes staged files afterwards so
  a reviewer cannot modify the workspace.
- Codex runs as a non-interactive CLI subprocess with a structured output
  schema.
- Codex output is normalized to a common report schema; findings can never
  dismiss a local hard failure, and unresolved findings block
  `studio_reviewed`.

## Website (`web/index.html`)

Single-page graphite console served at `http://127.0.0.1:8001/`: neon logo
beside the mapping-run form, streaming generation status (SSE), anchors,
palette approval with preview, Codex timing/palette actions, hash-bound review
APIs, playtest evidence entry, install, and release-status rendering.
The Generate button only ever calls `POST /api/generate`. Do not auto-stamp
`release_candidate`.

## Legacy pipeline (do not restore)

The pre-premium pipeline still exists behind `python -m beatforge --legacy`
and its tests. Default `beatforge` CLI generation now calls
`premium.run_premium_pipeline` (`generate_map.py --profile official-premium
--full-spread`). These modules remain marked `LEGACY` in their docstrings:

`analyze.py` (librosa DSP) → `place.py` (rule-based placement) →
`critic.py` → `export_beatsaber.py`, with `chart.py`, `styles.py`,
`provenance.py`, and the orphaned `skill_checker.py` as support modules.

Nothing in the studio path imports them. Do not wire them back into
`api.py`/`premium.py`; new generation work belongs in the
`beat-saber-mapping` skill. `tools/corpus/*` remains a BeatSaver study
toolkit, separate from the official corpus.

## Repository layout

```
src/beatforge/            FastAPI studio (api, premium bridge, Codex review, install)
skills/beat-saber-mapping Canonical skill: scripts, tests, references, agents
.codex/                   Byte-identical portable skill copy (verified by CI + skill-lock.json)
web/                      Studio console + brand assets
tools/                    sync_portable_skill.py, corpus study toolkit
tests/                    Application suite (incl. Codex review mock tests)
docs/                     Architecture, Windows setup, corpus audits, layout notes
.github/workflows/        Skill drift check
```

Runtime data (`data/jobs`, provider settings, corpora, audio) is local-only
and git-ignored.
